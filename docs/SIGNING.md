# 插件签名与可信来源

目标：第三方开发的插件提交给你之后，**只有你审查过并签名的，安装后才会标注绿色「可信来源」**；没有签名的一律标黄色「未经安全验证」。

## 它保证什么，不保证什么

签名表示：**"持有这把私钥的人，审查过这份内容，并认为它安全。"**

- 签名绑定的是**内容**（每个文件的哈希）、**插件 id** 和**版本号**。改动任何一个文件、增删文件、换版本号，签名都会失效。
- 签名的是内容而不是 zip 文件本身，所以重新压缩、增加一层顶层文件夹，都不影响签名。
- 安装之后，每次启动扫描时都会重新校验。安装后有人改了插件文件，会从绿色变成红色「签名无效」。
- 它**不保证**插件本身没有漏洞，也不保证你的审查没有疏漏——"可信"的程度取决于你的审查。

## 一次性准备

在项目根目录：

```bash
# 1. 编译签名工具
cargo build --release -p nuthusk-sign        # 生成 target/release/nuthusk-sign

# 2. 生成你的密钥对
nuthusk-sign keygen my-signing-key
#   my-signing-key.key   私钥：务必保密，不要提交到仓库，也不要放进安装包
#   my-signing-key.pub   公钥
```

3. 把公钥放进 `src-tauri/trusted_keys.json`（`keygen` 会打印好可以直接粘贴的内容），然后**重新编译 NutHusk**：

```json
{
  "keys": [
    { "name": "你的名字或组织", "public": "nuthusk-ed25519-public:……" }
  ]
}
```

公钥是编译进程序的，所以别人无法在用户机器上悄悄添加受信任的签名者。`trusted_keys.json` 为空时（默认），所有插件都显示「未经安全验证」。

> **务必备份私钥。** 私钥丢了，就没法再给新插件签名；换一把新的，需要重新编译并发布新版 NutHusk。私钥泄露则意味着别人可以冒充你签名，请立即换钥并发布新版。

## 审查并签名

收到第三方提交的插件包后：

```bash
nuthusk-sign sign their-plugin.nut --key my-signing-key.key
```

工具会先列出插件的名称、版本、声明的权限、后端命令和内容摘要，并要求你输入 `yes`，表示你已经审查完毕。输出是 `their-plugin.signed.nut`，不会覆盖原文件。把这个文件发给用户。

验证：

```bash
nuthusk-sign verify their-plugin.signed.nut --keys src-tauri/trusted_keys.json
# 可信来源：由「你的名字」签名，内容未被改动
```

## 审查清单（建议）

签名之前，至少过一遍：

1. **plugin.json**：`permissions` 是否和功能相符？有没有要 `network` 却用不上的？
2. **后端命令**：`backend.command` 是什么？各系统的专用配置是否都合理？有没有指向包里你没法审查的二进制文件？
3. **后端代码**：逐个文件读完。重点：读写了哪些路径、发起了哪些网络请求、启动了哪些子进程、有没有混淆或下载并执行代码的逻辑。
4. **界面代码**：有没有向外发送用户输入的数据？引用了哪些外部地址？（没有 `network` 权限时界面本来就联不了网，但要看它为什么需要。）
5. **依赖**：随包带了哪些第三方库？带了 `node_modules` 之类的大目录吗？无法审查的部分，要么要求对方精简，要么不签。
6. **二进制文件**：只要有你无法审查的二进制，就不要签名，或者要求对方提供源码并由你自己编译。
7. **版本**：每次更新都要重新审查并重新签名——旧签名不会自动覆盖新版本。

## 状态一览

| 情况 | 标识 | 能否安装 |
|---|---|---|
| 受信任的密钥签名，内容一致 | 绿色「可信来源」 | 可以 |
| 没有签名 | 黄色「未经安全验证」 | 可以（确认框里会提示风险） |
| 签名者不在 `trusted_keys.json` 里 | 黄色「未经安全验证」，注明密钥 ID | 可以（同上） |
| 有签名但内容对不上 / 格式损坏 | 红色「签名无效」 | **不可以** |

## 技术细节

- 算法：Ed25519。
- 内容摘要：SHA-256( 按路径排序后，逐个文件的 `路径 \0 文件哈希(十六进制) \n` )，不含 `signature.json` 自身。路径相对插件根目录，用 `/` 分隔。
- 被签名的消息：`NutHusk-Plugin-Signature-v1\nid=<id>\nversion=<版本>\ndigest=<摘要>\n`。
- `signature.json`：`{ "version": 1, "algorithm": "ed25519", "keyId": "<公钥 SHA-256 的前 16 位十六进制>", "signature": "<base64>" }`，放在插件根目录。
- 密钥文件格式：`nuthusk-ed25519-private:<base64 的 32 字节种子>`、`nuthusk-ed25519-public:<base64 的 32 字节公钥>`。

## 目前没有做的

- **吊销**：目前没有在线吊销机制。需要撤销某把密钥或某个插件时，改 `trusted_keys.json` 并发布新版 NutHusk。
- **多级信任 / 密钥轮换**：支持在 `trusted_keys.json` 里放多把公钥（新旧并存），但没有更细的信任等级。
