# NutHusk 插件开发计划与设计思路

整理日期：2026-10-31  
状态：阶段 A 五个插件首版已实现并通过本地验证，源码位于独立 NutHusk-Plugins 仓库；已生成未签名试用包，尚未签名发布。阶段 B/C 与下载器仍为规划。  
用途：独立交接文档，可移出当前仓库；不依赖仓库内其他文档才能理解。

## 1. 产品方向与已确认约束

NutHusk 是承载独立工具的轻量桌面工作台。插件负责参数设置、交互、预览和结果呈现；成熟的底层处理能力优先复用现有工具。插件的同一处理动作应能被界面、批量执行和流水线复用。

已确认的产品要求：

- 保留插件自由设计 HTML/CSS/JavaScript 界面的能力，暂不迁移原生界面体系。
- 不要求所有插件都自行编写底层算法；转码、压缩等优先调用成熟引擎。
- 界面调用底层工具的 CLI / API，不采用模拟点击其他软件窗口的方式。
- 插件包独立分发，计划在 NutHusk-Plugins 项目中开发、维护；不把全部插件附带进宿主分发包。
- 主程序保持轻量；额外 CLI 可以单独提供。外部引擎不因一个插件需要就全部塞进主程序。
- 下载器后续再讨论，本次仅保留需求摘要，不排入近期开发。
- 本文中的动作名、数据结构和命令描述均为设计建议，不代表已有 API 或已经可以运行的命令。

## 2. 数据、记录与退出行为

### 2.1 业务数据仅在运行期保留

用户输入、输出、处理结果、传入文件的内容、解析出的信息及任务列表，只在软件运行期间由插件和宿主内存暂存。切换标签可以保留本次状态；彻底退出软件后，不恢复任何业务输入输出或处理历史。关闭标签时是否提前释放由生命周期策略决定，但不得为恢复状态而写盘。

不得把业务内容写入 localStorage、IndexedDB、数据库、会话文件、配置文件、磁盘日志、崩溃上下文或自动生成的历史记录。流水线即使保存步骤定义，也不得把本次输入输出和实际文件路径作为运行历史夹带保存。

这些要求也适用于被调用的外部工具：不能只清空 HTML 界面，却留下外部引擎的日志、会话、URL 清单或结果索引。

### 2.2 区分内存结果和用户产物

| 数据类型 | 处理原则 |
| --- | --- |
| 输入文本、转换结果、媒体信息、预览 | 内存暂存，退出后不恢复 |
| 下载地址、任务队列、进度、失败原因 | 内存暂存，不保存任务历史 |
| 用户主动导出或下载的文件 | 作为明确产物写到用户选择的位置，退出不删除 |
| 插件文件、固定 emoji 数据、外部引擎本体 | 属于程序资源，不属于业务历史 |
| 安装信息及软件设置 | 沿用宿主既有机制，本计划不扩大持久化范围 |
| 复制到系统剪贴板的内容 | 由系统管理；不能宣称宿主退出即自动清空系统剪贴板历史 |

默认优先采用内存、管道和流式处理。若引擎必须写业务中间文件，不得直接把“退出后删除”当成“从未落盘”；应先确定是否可避开该写盘行为，再决定功能是否采用。这类取舍在实现前单独确认。

正常退出应结束所属子进程、取消任务并释放内存。强制结束进程或系统崩溃时不能依靠退出回调兜底，因此默认就应避免持久化业务历史。

### 2.3 emoji 的准确定位

名称使用“常用 emoji 表”或“emoji 速查”，不使用“收藏夹”。

- 提供内置、固定的常用 emoji。
- 用户只能浏览与复制，不编辑、不添加、不删除。
- 不做收藏、最近使用、使用次数、自定义分组或同步。
- 无需后端，也无需业务数据持久化。

## 4. 各插件的边界与验收要点

### 4.1 文本行处理

输入为文本，输出为文本。首版优先完成行去重，再增加排序与空行清理。

需明确并测试：是否保留原顺序、大小写比较、首尾空白处理、空行是否参与去重、Windows/Unix 换行及末尾换行行为。界面按钮和流水线动作调用同一个转换函数。

验收：重复点击不会积累副作用；中文及混合换行正确；异常不把原文写入日志；退出重开不恢复文本。

### 4.2 Base64 编解码

文本模式必须正确处理中文、emoji 和 UTF-8，不直接把仅适用于字节字符串的调用当成完整文本方案。非法输入给出可读提示，不把乱码当成成功。

文件模式涉及二进制与大文件，应作为单独扩展；明确 Base64 是编码，不是加密。不要为了传文件而默认把所有二进制转成 Base64 在宿主消息中搬运。

### 4.3 常用 emoji 表

内置固定表情与必要的说明，点击即可复制；复制成功反馈仅在本次运行显示。

验收：组合表情和变体选择符不被截断；没有编辑或收藏入口；不记录使用频率；没有为该插件新增持久化存储。

### 4.4 世界时间对照

以城市和 IANA 时区标识为基础，例如 Asia/Tokyo，而不是把国家硬编码成一个 UTC 偏移。同一国家可能有多个时区，夏令时也可能随日期变化。

首版提供固定常用城市对照与临时时间选择；不保存用户查询、城市选择历史或计算结果。显示日期跨天差异；对夏令时切换时不存在或重复的当地时间定义明确处理方式。

### 4.5 图片调整与水印

首版先实现单文件操作，再复用相同动作处理文件列表。

- 图片调整：等比缩放、不放大选项、目标尺寸、输出格式、质量。
- 水印：先实现文字，支持位置、边距、颜色、透明度和字号；图片水印后续增加。
- 预览参数和最终处理参数保持同一含义，不能只在浏览器里看起来正确。
- 明确 EXIF 方向、透明背景、字体可用性及元数据保留策略。
- 默认另存，明确输出命名和重名处理，不静默覆盖源文件。

实现前用代表性大图及批量样本比较浏览器处理与 ImageMagick。浏览器适合轻量预览，重型处理可交给本地引擎；不要为了统一形式强制所有图片都启动外部进程。

### 4.6 视频压缩/转码与提取音频

用 ffprobe 获取结构化媒体信息，用 FFmpeg 执行实际处理。插件提供任务导向的预设和界面，不重新实现编解码器，也不操作其他软件的 GUI。

- 压缩界面先提供常用质量预设、目标分辨率及音频保留设置。
- 提取音频区分“直接复制音轨”和“重新编码”，明确兼容格式。
- 输入可能包含多音轨、字幕、旋转信息；首版需说明选择与保留策略。
- 显示进度、允许取消，失败给出简洁原因；不把完整工具输出原样写入永久日志。
- FFmpeg/ffprobe 的能力随具体构建变化，启动前检测版本与所需编码器，不能只判断 exe 文件存在。

验收：单文件、批量和流水线使用相同参数语义；长任务不中断普通 UI；失败或取消时保留源文件；默认不留下被当作成功结果的半成品。

### 4.7 TOTP 验证器

用户确认 https://plain-mud-12fc.fond.workers.dev/ 是 TOTP 验证器，功能方向类似 Android 上的 Google Authenticator。此前未能读取该页面，以上归类以用户说明为准。

首版支持手动输入密钥或粘贴 TOTP 配置 URI，显示账号/服务名称、动态验证码、有效期倒计时，支持一键复制和本次运行内管理多个临时条目。二维码导入可在后续增加。

严格沿用业务数据只在内存保留的要求：账号、密钥、配置 URI 和验证码均不保存、不上传、不进入日志或会话恢复；软件彻底退出后全部丢失，下次使用需重新导入。界面必须明确说明这是临时验证工具，不能作为长期账号保管、同步或备份工具。系统剪贴板由系统管理，不承诺退出软件会清除其历史。

采用成熟 TOTP 实现；发布前用标准测试向量验证，检查配置参数、时间边界和系统时钟变化，非法密钥或不支持的参数明确提示，不静默使用其他参数。关闭界面/退出时释放计时器和敏感数据引用；不宣称能保证操作系统层面的内存安全擦除。首版不包含 HOTP 或云同步。

## 5. 共享引擎与插件边界

插件按用户任务划分，依赖按底层能力共享。例如视频压缩与音频提取可以有独立入口，共用一份 FFmpeg；图片调整与水印可共用图片引擎。

| 层次 | 职责 |
| --- | --- |
| 插件界面 | 文件选择、参数设置、预览、进度和结果展示 |
| 插件处理动作 | 校验输入，将参数转换为确定的处理请求，返回结构化结果 |
| 引擎适配层 | 探测能力、组装参数数组、启动进程、处理退出码和进度 |
| 成熟引擎 | 编解码、图像处理、下载等实际工作 |
| 宿主 | 通信、任务生命周期、取消、资源协调及跨插件衔接 |

外部工具优先允许用户指定本机路径；按需安装和多插件共享作为宿主能力逐步补充。Python/Node 解释器管理已存在，不等于 FFmpeg、ImageMagick 等工具的共享依赖管理已经完成。

调用进程时使用独立参数数组，不把路径、URL 或用户文本拼成 shell 命令。工具版本、来源和平台匹配方式需要明确；引入或分发上游代码与二进制时按实际许可证处理。

## 6. 一套动作，服务界面、批量与流水线

每个可处理数据的插件先确定下面七项，再编写界面：

| 项目 | 需要写清的内容 |
| --- | --- |
| 输入 | 文本、一个文件、文件列表、URL 或其他类型 |
| 参数 | 名称、类型、默认值、取值范围 |
| 输出 | 文本、文件引用、文件列表或结构化信息 |
| 依赖 | 无依赖、解释器、特定外部引擎及必要能力 |
| 长任务 | 是否需要进度、取消和异步任务 ID |
| 批量 | 是否支持、并发策略、失败后继续还是停止 |
| 数据去向 | 内存结果或用户明确选择的输出文件；不保存业务历史 |

建议形成稳定的结果结构：成功状态、输出文本/文件引用、必要元信息和可读错误。字段与版本在实现时再定，不在本文虚构现有协议。

界面按钮、批量入口和流水线都调用相同动作。纯前端插件可以复用纯函数；需要 CLI 无界面执行时再决定是否提供可复用的独立处理模块或后端适配层，不能把“宿主内可以调用前端动作”等同于“现有 CLI 能直接执行任意 HTML 逻辑”。

文件批处理优先传路径或宿主管理的文件引用，避免在消息里传整份大文件。文件路径本身也属于本次业务数据，不进入自动保存的执行历史。

## 7. 宿主能力：已有基础与待补部分

整理时的基础：宿主使用 Tauri/Rust＋本地 HTML/CSS/JavaScript；插件界面在沙箱 iframe 中运行，插件后端为独立进程，通过单行 stdio JSON-RPC 通信。已有动作、前端动作回调、快捷流水线及 CLI 开发工具基础，需要保持旧插件兼容。

当前普通后端调用期限为 15 秒；CLI 后端单次探测/执行路径也存在 5 秒等待限制。不能把这些短调用直接用于长时间转码或下载，也不应仅全局放大超时。

| 能力 | 状态与计划 |
| --- | --- |
| 简单文本动作、HTML 插件、后端 RPC | 复用现有基础 |
| 文本型动作串联 | 复用并验证已有流水线，不能假定已有完整文件流水线 |
| 文件列表输入与结构化产物传递 | 在图片批量前明确协议，按需补齐 |
| 长任务提交、进度、查询、取消 | 音视频插件前补齐；提交后快速返回任务 ID |
| 批量调度 | 区分文件并发与单任务内部并行；CPU 密集任务默认保守 |
| 外部工具共享、版本与能力检测 | 先提供小型适配层，随真实插件需要扩展 |
| 状态持久化 | 不新增输入输出历史或任务会话持久化 |

长任务应由宿主协调，不绑定某一个页面是否当前可见。关闭标签、用户取消、空闲回收与彻底退出分别定义行为；执行中的任务不能被现有闲置回收误杀，彻底退出也不能遗留所属后台进程继续写文件。

不要为了计划中的所有插件先建设复杂通用框架。P1 不依赖长任务；P2 暴露的真实需求再推动文件协议；P3 之前完成长任务最小闭环。

## 8. 开发顺序

### 阶段 A：轻量插件样板

实施记录（2026-10-31）：已完成文本行处理、Base64、常用 emoji 表、世界时间对照、TOTP 五个纯前端插件。插件仓库完整 19 项测试通过，含 18 个 TOTP 标准向量；五包完成 CLI 校验/打包/验证与 Edge 沙箱、主题和窄屏检查。详情见插件仓库 docs/STAGE_A.md；本地主项目未改变功能代码，未修改发布索引、未签名或推送。

依次完成文本去重、Base64、常用 emoji 表、世界时间对照，再完成 TOTP 验证器。TOTP 单独通过正确性与无持久化验收后发布。产出可复用的插件目录模板、样式与动作组织示例。

完成条件：单个插件可独立打包和安装；适用功能能通过动作调用；鼠标与键盘入口一致；退出重开不恢复输入输出；没有新增业务数据落盘。

### 阶段 B：图片与文件批量

先做图片调整的单文件闭环，再做文字水印；之后补齐文件列表、命名规则、取消和批量结果。确定是否需要共享 ImageMagick，以及依赖如何找到。

完成条件：多文件分别返回结果；单项失败不误报整批成功；无静默覆盖；预览与输出一致；依赖缺失、取消和异常退出有明确行为。

### 阶段 C：长任务与音视频

先完成任务提交—进度—取消—结果的最小闭环，再做视频压缩/转码，随后复用引擎完成音频提取。

完成条件：超出普通 RPC 期限的任务正常运行；正常退出回收所属任务和子进程；GUI 与批量动作参数一致；可明确把输出文件交给下一插件。

### 阶段 D：下载器，暂缓

近期不开发，不因下载器需求阻塞 A—C。保留下一节的需求，后续单独确定解析范围、引擎组合和命令入口。

## 9. 下载器需求备忘，暂不实施

目标为一套下载能力的两个入口：

- 普通图形模式：以 Downbit、Gopeed 的简洁操作为体验参考，尽量做到粘贴链接、自动识别、选择必要选项后下载；高级参数折叠。
- 批量/命令模式：接收多行链接、链接清单或标准输入，控制任务并发、单文件连接数、限速、重试，并支持终端操作与后续流水线。

链接解析与实际下载分离。普通直链、多站点媒体页面、需要登录的分享链接不是同一种输入，不能把“多线程下载”当成“任意网址都可解析”。

待评估组合：aria2 负责常规及多连接下载；yt-dlp 负责支持的媒体网站解析；FFmpeg 负责必要的合并和转换。是否采用 Gopeed 核心或扩展体系尚未决定，不在此锁定选型。

UI 与命令复用动作和适配逻辑；是否让命令行控制已经运行的 GUI 队列，后续再明确，不能默认两种进程天然共享内存。

任务、URL、认证信息、解析结果、进度和失败记录不保存历史；软件彻底退出停止所属下载，不自动恢复上次队列。下载文件作为用户产物保留，外部工具的会话/日志/断点控制文件要单独审查；实现跨次启动续传会涉及持久化取舍，不默认加入。

## 11. 开工前的最小交接清单

1. 确定本次只做哪个插件，以及首版明确不包含的扩展功能。
2. 写清输入、参数、输出、依赖、长任务、批量和数据去向七项。
3. 先完成可独立验证的处理动作，再接界面；保持现有插件协议兼容。
4. 验证中文路径、空输入、大文件、取消、依赖缺失、输出重名与错误提示。
5. 核对输入输出没有被配置、日志、外部引擎或会话恢复机制保存。
6. 验证打包、安装、单次调用及适用的流水线；涉及长任务时额外验证退出回收。
7. 插件在 NutHusk-Plugins 中独立维护和分发；宿主仅增加本阶段确有需要的通用能力。
